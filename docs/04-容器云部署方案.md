## 1 平台概述

- 容器云平台 = **K8s 集群 + 联通定制可视化界面**，用于应用容器化部署。
- 优势：资源分配灵活、多服务器统一管理、容器故障自动迁移。
- 容器是镜像的运行实例（独立进程与隔离环境）；镜像是只读"模板"，打包应用代码、依赖与运行环境。

### 4.2 Dockerfile 示例（解析/AI 服务）

基础镜像较精简，需配置临时 yum 源并写入 /etc/hosts 后安装依赖：

```dockerfile
FROM 130.36.8.236:8443/library/uos-server-20-1070u1a:latest

# 配置临时 yum 源（zcgf-nginx.zcgf-test.com 为临时域名，无内网 DNS，需 hosts 映射 130.36.8.237）
RUN printf '[myuos-BaseOS]\nname=UOS Server BaseOS\nbaseurl=http://zcgf-nginx.zcgf-test.com/myuos/BaseOS\nenabled=1\ngpgcheck=0\n\n[myuos-AppStream]\nname=UOS Server AppStream\nbaseurl=http://zcgf-nginx.zcgf-test.com/myuos/AppStream\nenabled=1\ngpgcheck=0\n' > /etc/yum.repos.d/myuos.repo \
 && echo "130.36.8.237 zcgf-test.com" >> /etc/hosts \
 && yum -y install python3 python3-pip gcc && yum clean all

WORKDIR /app
COPY requirements.txt .
RUN pip3 install --no-cache-dir -r requirements.txt
COPY . .
EXPOSE 8000
CMD ["python3", "main.py"]
```

（Java 后端：同样基于该基础镜像，yum 安装 jdk17 或 COPY 自带 JDK，`java -jar app.jar` 启动。）

### 5.3 域名是前置条件

HTTP 服务类型**强制域名访问**，因此域名必须在 W1 与云资源一并确认（平台分配或申请流程），否则无法提供对外入口。同时确认 80 端口与其他项目的分隔方式（本项目接口统一在 `/api` 前缀下，便于 Uri 映射区分）。

## 9 DWG 图纸转换部署（ODA File Converter）

### 9.1 技术背景

通信工程竣工图通常是 **DWG 格式**（AutoCAD 专有二进制格式），而项目解析服务使用的是 **ezdxf**——它只能读取 **DXF 格式**（DWG 的开放交换格式）。

前置流程：

```
DWG（用户上传） → ODA File Converter 转换 → DXF（开放格式） → ezdxf 解析 → 图元提取 + 量算
```

### 9.2 ODA File Converter 现状（2025-2026 验证结论）

| 项目 | 状态 |
|------|------|
| **产品名** | ODA File Converter（命令行/桌面双版本） |
| **免费版** | ✅ 仍可免费使用，需官网注册账号下载 |
| **平台** | Windows（`.exe`）、**Linux（`.deb`/`.rpm`/AppImage）**、macOS |
| **官网** | https://www.opendesign.com |
| **Linux 架构** | x86_64，gcc 4.9+（glibc 2.19+） |
| **与联通云兼容性** | ✅ **UOS Server 20（基于 Linux）**，架构与依赖完全匹配 |

**关键结论：ODA File Converter 命令行工具**可以免费用于生产环境，无需购买 SDK 授权。**注意**：2023 年后 ODA 官网已不再单独展示"ODA File Converter"下载页面，免费版需注册 opendesign.com 账号后在 Dashboard 中获取 Linux 版安装包（`.deb` 或 AppImage）。

### 9.3 Docker 容器内部署

本项目 `ai.Dockerfile` 已预留 ODA 部署代码（见 `deploy/docker/ai.Dockerfile` 第 34~42 行），注释部分即为完整部署方案：

```dockerfile
# AI 服务镜像（ai.Dockerfile）
FROM 130.36.8.236:8443/library/uos-server-20-1070u1a:latest

# ...（yum 安装 python3, gcc 等依赖，见已有内容）

# DWG 支持（可选）：把 ODA File Converter 的 Linux 安装包（.rpm）放入 deploy/oda/ 后取消下面注释。
# Linux 版 ODAFileConverter 依赖 Qt/X11，容器内无 DISPLAY，需 Xvfb 虚显。
# xorg-x11-xauth 不可省：xvfb-run 依赖 xauth，缺失会直接报 "xauth command not found"。
# 容器云无外网，安装包必须随构建上下文带入，不能在运行时下载。
# COPY deploy/oda/ /opt/oda/
# RUN yum -y install xorg-x11-server-Xvfb xorg-x11-xauth /opt/oda/*.rpm \
#  && rm -rf /opt/oda \
#  && test -x /usr/bin/ODAFileConverter
# ENV AI_ODA_CONVERTER_PATH=/usr/bin/ODAFileConverter
```

**部署步骤：**

1. 注册 opendesign.com 账号 → 下载 Linux 版 ODA File Converter（`.rpm` 格式，适配 UOS Server）
2. 将安装包放入 `deploy/oda/` 目录：
   ```
   deploy/oda/
   └── ODAFileConverter_Linux_64.rpm
   ```
3. 取消 `ai.Dockerfile` 第 34~42 行的注释
4. 重新构建镜像：
   ```bash
   docker build -f deploy/docker/ai.Dockerfile \
     -t 130.36.8.236:8443/<namespace>/preaudit-ai:v0.2.0-20261201 \
     .
   ```

**容器化注意事项：**
- ODA File Converter 依赖 Qt/X11，容器内无物理显示器（无 `DISPLAY` 环境变量），**需 Xvfb 虚显**（Virtual Frame Buffer）
- 代码层应检测 `DISPLAY` 变量，若无则自动用 `xvfb-run` 包裹 ODA 进程
- 安装包必须随构建上下文带入，容器云无外网，不能在运行时 `yum install` 或 `apt install`

### 9.4 命令行调用方式

**批量转换命令格式：**

```bash
# 基本语法
ODAFileConverter <输入目录> <输出目录> <DXF 版本> <输出格式> <是否递归> <是否审计> <文件过滤>

# 实际执行示例
ODAFileConverter /data/uploads/project-001/dwg /data/uploads/project-001/dxf ACAD2018 DXF 0 1 "*.dwg"
```

**参数说明：**

| 参数 | 含义 | 推荐值 |
|------|------|--------|
| 输入目录 | DWG 文件存放位置 | PVC 挂载的上传目录 |
| 输出目录 | DXF 输出位置 | PVC 挂载的解析缓存目录 |
| ACAD2018 | DXF 输出格式版本 | ACAD2018 或 ACAD2021（ezdxf 兼容性好） |
| 输出格式 | 目标格式 | DXF |
| 是否递归 | 是否遍历子目录 | 0（一期不需要） |
| 是否审计 | 是否修复损坏文件 | 1（建议开启，自动修复小问题） |
| 文件过滤 | 通配符 | `*.dwg` |

### 9.5 Python 代码集成示例

在 AI 服务中封装 ODA 调用逻辑（建议写入 `ai-service/app/services/dwg_converter.py`）：

```python
import os
import subprocess
from pathlib import Path
from app.core.config import get_settings

def convert_dwg_to_dxf(input_dwg_dir: str, output_dxf_dir: str) -> dict:
    """
    批量将目录下的 DWG 文件转换为 DXF 格式。
    
    Args:
        input_dwg_dir: 输入目录（DWG 文件存放位置）
        output_dxf_dir: 输出目录（DXF 文件存放位置）
    
    Returns:
        {"success": True, "converted_files": [...], "error": None}
        或
        {"success": False, "converted_files": [], "error": "错误信息"}
    """
    oda_path = os.environ.get("AI_ODA_CONVERTER_PATH", "/usr/bin/ODAFileConverter")
    
    if not os.path.exists(oda_path):
        return {
            "success": False,
            "converted_files": [],
            "error": f"ODA File Converter 未安装：{oda_path} 不存在"
        }
    
    cmd = [
        oda_path,
        input_dwg_dir,
        output_dxf_dir,
        "ACAD2018",      # DXF 版本（ezdxf 兼容性好）
        "DXF",            # 输出格式
        "0",              # 不遍历子目录
        "1",              # 开启审计修复（自动修复损坏文件）
        "*.dwg"           # 仅处理 DWG 文件
    ]
    
    try:
        result = subprocess.run(
            cmd,
            capture_output=True,
            text=True,
            timeout=600   # 10 分钟超时（大图纸可能较慢）
        )
        
        if result.returncode != 0:
            return {
                "success": False,
                "converted_files": [],
                "error": f"ODA 转换失败（返回码 {result.returncode}）：{result.stderr}"
            }
        
        # 统计转换成功的文件
        output_path = Path(output_dxf_dir)
        converted = [
            str(f.relative_to(output_path))
            for f in output_path.rglob("*.dxf")
        ]
        
        return {
            "success": True,
            "converted_files": converted,
            "error": None
        }
    except subprocess.TimeoutExpired:
        return {
            "success": False,
            "converted_files": [],
            "error": "ODA 转换超时（超过 10 分钟）"
        }
    except Exception as e:
        return {
            "success": False,
            "converted_files": [],
            "error": f"ODA 转换异常：{str(e)}"
        }
```

### 9.6 Xref 外部参照文件处理

**问题说明：** 部分 DWG 图纸依赖外部参照文件（`.dwg` 引用其他图纸），ODA 转换时若参照文件缺失，会生成部分空白或报错。

**应对策略：**
1. 上传时校验：要求用户上传完整图纸包（主图纸 + 所有 Xref 引用文件放在同一目录）
2. 转换后校验：检查 DXF 中是否有空图层、零线元等异常
3. 返回明确错误：转换失败时提示用户"外部参照文件缺失"，引导用户补充上传
